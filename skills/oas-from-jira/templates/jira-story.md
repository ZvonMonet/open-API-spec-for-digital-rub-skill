# Шаблон Story

**Story** фиксирует ценность для пользователя и **критерии приёмки** — проверяемые условия, по которым принимается результат. Связана с Task связью **relates to** ([[jira-task]]).

Критерии приёмки — **высший приоритет** среди источников: AC в Story → Task → context → knowledge. Если AC противоречит Task или knowledge, skill следует AC и отмечает расхождение в отчёте.

## Поля Jira

| Поле | Что указать |
|---|---|
| Тип | `История` (Story) |
| Summary | Действие пользователя: `Клиент открывает кошелёк цифрового рубля в приложении` |
| Description | По шаблону ниже |
| Labels | Метка проекта skill (сейчас `ai-skill-sotnikov`) |
| Linked issues | Task — `relates to` |

## Шаблон Description

```markdown
## История *
Как <роль>, я хочу <действие>, чтобы <ценность>.

## Контекст
Описание фичи и сценарии — в связанной задаче <KEY>.

## Критерии приёмки *
Формат: идентификатор, название, Дано / Когда / Тогда. Один критерий — одно проверяемое поведение.

### AC-01. <Название>
Дано <предусловие>
Когда <действие>
Тогда <ожидаемый результат: что вернёт система, какой статус, какое сообщение>

### AC-02. <Название>
...

## Вне рамок истории
- <Что сознательно не проверяется в этой истории>

## Допущения
- <Что принято без подтверждения>
```

## Требования к хорошему критерию

| Требование | Плохо | Хорошо |
|---|---|---|
| Проверяемый | «Кошелёк открывается быстро» | «Ответ на запрос создания заявки — не дольше 2 с (p95)» |
| Однозначный | «Показывается ошибка» | «Возвращается отказ с кодом `WALLET_ALREADY_EXISTS`» |
| Одно поведение | «Клиент принимает договор и создаёт ключи» | Два отдельных AC |
| Без реализации UI | «Красная кнопка» | «Клиенту сообщается, что кошелёк уже открыт» |

## Как skill использует критерии

| Часть AC | Во что превращается |
|---|---|
| `AC-NN` | `x-acceptance-criteria` у операции; строка в матрице покрытия отчёта |
| Дано | Предусловие → проверка и код ошибки при нарушении |
| Когда | Операция (метод + путь) и тело запроса |
| Тогда | Код ответа, схема ответа, статус, бизнес-код ошибки, пример |

Каждый AC должен быть покрыт хотя бы одной операцией или ответом. AC, который относится только к интерфейсу, отмечается в отчёте как «вне OAS».

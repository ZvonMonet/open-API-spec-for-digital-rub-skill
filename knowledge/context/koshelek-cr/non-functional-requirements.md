# КошелёкЦР — нефункциональные требования

> [!note] Пример контекста
> Значения со статусом **Принято** выбраны для учебного примера; в реальном проекте их задают архитектор, ИБ и эксплуатация.

Идентификаторы: `NFR-<область>-<номер>`. Колонка «В OAS» показывает, во что требование превращается в спецификации. Требования без отражения в OAS (мониторинг, хранение) приведены для полноты и в артефакт не переносятся.

Статусы: **Подтверждено** — согласовано с владельцем продукта; **Принято** — значение по умолчанию для примера; **Норма** — из закона или требований Банка России.

---

## 1. Производительность и время ответа

| ID | Требование | Статус | В OAS |
|---|---|---|---|
| NFR-PERF-01 | Синхронные операции модуля — не дольше 2 с (p95), включая вызовы внешних систем. | Подтверждено | `description` операций; асинхронность для шагов, которые не укладываются (NFR-PERF-02) |
| NFR-PERF-02 | Операции, зависящие от выпуска сертификата, открытия счёта или зачисления на платформе, выполняются асинхронно: ответ `202` и ресурс со статусом. | Принято | `202` + `Location` (OAS-ASYNC-01) |
| NFR-PERF-03 | Рекомендуемый интервал опроса статуса — 2 с, максимальное время ожидания на клиенте — 60 с, после чего клиент показывает «операция в обработке». | Подтверждено | `description` операции получения статуса |
| NFR-PERF-04 | Пропускная способность — до 50 запросов в секунду на модуль в пике. | Подтверждено | — |

## 2. Доступность и надёжность

| ID | Требование | Статус | В OAS |
|---|---|---|---|
| NFR-AV-01 | Доступность модуля — 99,9 % в месяц. | Подтверждено | — |
| NFR-AV-02 | При недоступности внешней системы модуль не теряет заявку или операцию: возвращает явную ошибку или оставляет объект в промежуточном статусе для доработки. | Принято | `503` / `504`, промежуточные статусы (BR-TIME-03) |
| NFR-AV-03 | Неопределённый результат на платформе (таймаут) уточняется запросом статуса на платформе; повторная отправка денежной операции без уточнения запрещена. | Принято | `description` операций пополнения и вывода |
| NFR-AV-04 | Повтор запроса клиента с тем же `Idempotency-Key` в течение 24 часов возвращает исходный итоговый результат. Ключ обязателен для каждого изменяющего запроса. Ответы 5xx по ключу не сохраняются — повтор выполняет запрос заново (BR-IDM-03). | Подтверждено | `components.parameters.IdempotencyKey` у каждого `POST` |
| NFR-AV-05 | Вызовы внешних систем повторяются по политике `RP-EXP` (экспоненциальная задержка с джиттером) — параметры и исключения в [[integrations#Политика повтора]]. После исчерпания повторов — правило из раздела системы в [[integrations]]. | Подтверждено | `description` операций; `503` / `504`; на диаграмме — `loop` ретрая |

## 3. Ограничение нагрузки

| ID | Требование | Статус | В OAS |
|---|---|---|---|
| NFR-RATE-01 | Создание заявок на открытие — не более 5 в час на клиента. | Подтверждено | `429` + `Retry-After` у операции создания заявки |
| NFR-RATE-02 | Создание операций пополнения — не более 1 в минуту на клиента. | Подтверждено | `429` + `Retry-After` |
| NFR-RATE-03 | Запросы статуса — не чаще 1 раза в секунду на ресурс. | Подтверждено | `429` у операций чтения статуса |

## 4. Безопасность

| ID | Требование | Статус | В OAS |
|---|---|---|---|
| NFR-SEC-01 | Клиентский API доступен только через API Gateway банка; аутентификация — токен доступа (JWT), выпущенный сервером авторизации банка. | Принято | `bearerAuth` (OAS-SEC-01) |
| NFR-SEC-02 | Канал клиент — банк: TLS 1.2+. | Норма / Принято | `servers` — только `https` |
| NFR-SEC-03 | Взаимодействие с платформой цифрового рубля — по требованиям Банка России к защите информации для участников платформы (СКЗИ, ГОСТ). | Норма | Только `info.description`; в клиентском API не описывается |
| NFR-SEC-04 | Классификация, маскирование и логирование данных — по [[sensitive-data]]. | Принято | `x-sensitivity`, `Cache-Control: no-store` |
| NFR-SEC-05 | Распоряжения по кошельку подписываются ключом ЭП клиента; модуль проверяет наличие подписи и передаёт её на платформу, не изменяя. | Принято | Поле `signature` в запросах операций |

## 5. Сроки и хранение

| ID | Требование | Статус | В OAS |
|---|---|---|---|
| NFR-RET-01 | Срок действия незавершённой заявки на открытие — 24 часа. | Подтверждено | Поле `expiresAt`, статус `EXPIRED` |
| NFR-RET-02 | Неподтверждённая операция пополнения или вывода истекает через 15 минут. | Принято | Поле `expiresAt`, статус `EXPIRED` |
| NFR-RET-03 | Заявки, согласия и операции хранятся не менее 5 лет (115-ФЗ). | Норма | — |
| NFR-RET-04 | ПДн граждан РФ хранятся в БД на территории РФ (152-ФЗ). | Норма | — |

## 6. Наблюдаемость и аудит

| ID | Требование | Статус | В OAS |
|---|---|---|---|
| NFR-OBS-01 | Каждый запрос имеет сквозной идентификатор; модуль передаёт его во внешние системы и возвращает клиенту. | Принято | `X-Request-Id` (OAS-HDR-02) |
| NFR-OBS-02 | Ошибки содержат `traceId` для поиска в журналах. | Принято | Поле `traceId` схемы `Problem` |
| NFR-OBS-03 | Журнал аудита фиксирует создание и смену статусов заявок и операций, принятие договора. | Норма (ГОСТ Р 57580.1) | — |

## 7. Совместимость

| ID | Требование | Статус | В OAS |
|---|---|---|---|
| NFR-CMP-01 | Версия API — в базовом URL (`/v1`); несовместимые изменения — новая мажорная версия. | Принято | `servers`, `info.version` (OAS-SRV-02, OAS-INFO-02) |
| NFR-CMP-02 | Клиент должен игнорировать неизвестные поля в ответах. | Принято | Без `additionalProperties: false` в ответах (OAS-SCH-05) |
| NFR-CMP-03 | Тексты для клиента формирует приложение по коду ошибки; API возвращает код и технический `title`. | Принято | Поле `code` схемы `Problem` |

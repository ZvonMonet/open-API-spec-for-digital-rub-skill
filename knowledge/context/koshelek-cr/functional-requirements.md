# КошелёкЦР — функциональные требования

> [!note] Пример контекста
> Продукт вымышленный, учебный. Для своего продукта скопируйте шаблон `skills/oas-from-jira/templates/context/functional-requirements.md` и заполните его.

Идентификаторы: `FR-<область>-<номер>`. На них ссылаются отчёт проверки (`-check.md`) и, при необходимости, `description` операций.

---

## 1. Продукт

| Параметр | Значение |
|---|---|
| Название | КошелёкЦР |
| Назначение | Модуль, через который небольшой банк даёт клиентам кошелёк цифрового рубля без переделки ядра банка (АБС). |
| Проблема | Подключение к платформе цифрового рубля дорого обходится среднему банку, а клиенты ждут эту функцию в приложении. |
| Потребитель API | Мобильное приложение банка (через API Gateway банка). |
| Провайдер API | Модуль КошелёкЦР. |
| Внешние системы | АБС банка, ЕСИА (Госуслуги), Платформа цифрового рубля Банка России, Антифрод — см. [[integrations]]. |

## 2. Пользователи

| Роль | Описание | В клиентском API |
|---|---|---|
| Клиент — физическое лицо | Открывает личный кошелёк, пополняет его, выводит средства. | Да |
| Клиент — индивидуальный предприниматель | Может открыть второй кошелёк — для предпринимательской деятельности. | Да |
| Сотрудник бэк-офиса | Разбирает заявки и операции на ручной проверке, отвечает на обращения. | Нет — отдельный API, вне текущих фич |

## 4. Общие требования

| ID | Требование | Источник |
|---|---|---|
| FR-GEN-01 | Все операции выполняет аутентифицированный клиент банка; клиент определяется по токену. | BR-GEN-01 |
| FR-GEN-02 | Клиент видит и изменяет только свои заявки, кошельки и операции; чужой ресурс — «не найдено». | BR-GEN-02, OAS-ERR-07 |
| FR-GEN-03 | Операции, создающие заявку или двигающие деньги, идемпотентны. | BR-IDM-01, BR-IDM-02 |
| FR-GEN-04 | Тип кошелька (`INDIVIDUAL` / `SOLE_PROPRIETOR`) указывается при открытии и далее определяет допустимые счета и лимиты. | BR-DR-OPEN-04, BR-DR-OPEN-05 |
| FR-GEN-05 | Баланс кошелька — данные платформы цифрового рубля, а не АБС. | BR-DR-OPS-03 |
| FR-GEN-06 | Пароль к кошельку хранится на устройстве клиента и используется приложением для локального доступа; в API не передаётся. | SCRUM-2194, SCRUM-2195 |
| FR-GEN-07 | Распоряжения по кошельку (пополнение, вывод) подтверждаются подписью клиента ключом ЭП, созданным при открытии кошелька; подпись формируется на устройстве. | BR-CNF-01, BR-DR-OPEN-10 |

## 5. Открытие кошелька

Сценарии и критерии приёмки — в SCRUM-2194 и SCRUM-2196.

| ID | Требование | Источник |
|---|---|---|
| FR-OPEN-01 | Клиент создаёт заявку на открытие кошелька выбранного типа. | SCRUM-2194 шаг 2 |
| FR-OPEN-02 | При создании заявки проверяются: совершеннолетие, гражданство РФ, статус ИП (для `SOLE_PROPRIETOR`), отсутствие кошелька этого типа, открытого через банк, отсутствие незавершённой заявки того же типа. | BR-DR-OPEN-01, 04, 05, 15 |
| FR-OPEN-03 | Модуль формирует ссылку для авторизации клиента в Госуслугах; результат авторизации ЕСИА возвращает на сервер банка. | BR-DR-OPEN-02 |
| FR-OPEN-04 | После авторизации модуль проверяет на платформе отсутствие счёта выбранного типа. | BR-DR-OPEN-04, 05 |
| FR-OPEN-05 | Клиент получает актуальную версию договора счёта цифрового рубля, ссылки на правила платформы и тарифы. | BR-DR-OPEN-08 |
| FR-OPEN-06 | Клиент принимает договор; модуль фиксирует согласие с версией и временем. Согласие со старой версией не принимается. Актуальная версия запрашивается у платформы (INT-DRP-02) в момент принятия, а не берётся из сохранённой на шаге 6 (решение 25.11.2026): иначе новая версия, опубликованная между шагами 6 и 8, не будет обнаружена. | BR-DR-OPEN-07, 09; INT-DRP-02 |
| FR-OPEN-07 | Клиент передаёт запрос на сертификат ключа проверки ЭП (CSR); закрытый ключ не передаётся. | BR-DR-OPEN-10 |
| FR-OPEN-08 | Перед открытием счёта заявка проходит проверку антифрода; при `REVIEW` заявка ждёт ручной проверки, при `DENY` отклоняется без раскрытия причин. | BR-AF-01…03 |
| FR-OPEN-09 | Для кошелька ИП модуль передаёт на платформу сведения об ИП из АБС; дополнительных сведений от клиента не требуется. Сведения об ИП модуль получает при создании заявки (запрос с `ownerType = SOLE_PROPRIETOR`, INT-ABS-01), сохраняет в заявке и на шаге 10 в АБС повторно не обращается. ИП открывает кошелёк в том же мобильном приложении. | BR-DR-OPEN-15 |
| FR-OPEN-10 | Клиент отслеживает статус заявки; после открытия заявка содержит идентификатор кошелька. При технической ошибке без возможности повтора (повторы исчерпаны, истёк срок ожидания, повтор не предусмотрен) заявка переходит в `FAILED` и содержит `errorCode`. | business-rules §8.1 |
| FR-OPEN-11 | Клиент может отменить заявку до передачи запроса на сертификат. | business-rules §8.1 |
| FR-OPEN-12 | Незавершённая заявка истекает через 24 часа. | SCRUM-2196 |
| FR-OPEN-13 | Клиент получает данные открытого кошелька: тип, статус, маскированный номер, баланс, дата открытия. | SCRUM-2194 шаг 13 |

## 6. Пополнение кошелька

Сценарий и критерии приёмки — в SCRUM-2195 и SCRUM-2197.

| ID | Требование | Источник |
|---|---|---|
| FR-TOP-09 | Клиент получает список своих кошельков для выбора получателя: тип, статус, маскированный номер. | SCRUM-2195 шаг 2 |
| FR-TOP-01 | Клиент получает список своих рублёвых счетов, с которых можно пополнить выбранный кошелёк. Для личного кошелька — текущие счета физлица; для кошелька ИП — расчётные счета ИП. | SCRUM-2195 шаг 4; BR-ACC-01, 04, 05 |
| FR-TOP-02 | Клиент указывает счёт-источник, кошелёк-получатель и сумму. | SCRUM-2195 шаги 6–7 |
| FR-TOP-03 | Проверки перед исполнением: счёт принадлежит клиенту, открыт, рублёвый, без ограничений; сумма > 0 и не больше доступного остатка; кошелёк активен (не заблокирован клиентом) и без ограничений на зачисление. | BR-ACC-01…06, BR-AMT-01, 02, business-rules §8.2 |
| FR-TOP-04 | Для личного кошелька физлица действует лимит пополнения 300 000 ₽ за скользящие 30 дней; для кошелька ИП лимита нет. Клиент может узнать остаток лимита; лимит учитывает и возвращает платформа. | SCRUM-2195 шаг 5; BR-DR-TOP-02 |
| FR-TOP-05 | Пополнение подтверждается подписью клиента (FR-GEN-07); отдельный OTP не требуется. | BR-CNF-01 |
| FR-TOP-06 | Исполнение: блокировка суммы на счёте в АБС → зачисление на платформе → списание блокировки. При отказе платформы блокировка снимается. | BR-DR-TOP-06, business-rules §8.4 |
| FR-TOP-07 | Клиент получает результат операции и баланс кошелька после зачисления. | SCRUM-2195 шаги 8–9 |
| FR-TOP-08 | Пополнение бесплатно для клиента. | BR-DR-TOP-05 |

## 7. Открытые вопросы

Открытых вопросов нет. Решения от 23.11.2026: лимит пополнения — за скользящие 30 дней, считает платформа; подтверждение пополнения — подписью ЭП без OTP; для кошелька ИП — только данные АБС, в том же приложении.

# Чувствительные данные в API

Файл задаёт, **какие данные считаются чувствительными, где их можно передавать и как маскировать**. Используется при подготовке OAS: каждое чувствительное поле схемы получает уровень, категорию и правило маскирования.

## 0. Как читать этот файл

**Идентификаторы:**
- `SD-<раздел>-<номер>` — правило обращения с данными;
- `MASK-<код>` — правило маскирования. В OAS указывается в `x-sensitivity.masking`.

**Тип правила** — как в [[business-rules]]:

| Тип | Значение |
|---|---|
| **Норма** | Требование закона, нормативного акта Банка России или отраслевого стандарта. |
| **Практика** | Общепринятое в банковском секторе правило; конкретные параметры задаёт банк. |
| **Решение** | Проектное решение для КошелёкЦР; можно менять по согласованию с ИБ. |
| **Проверить** | Требует подтверждения службой информационной безопасности банка. |

> [!important] Приоритет
> Внутренние политики ИБ банка и требования Банка России к участникам платформы цифрового рубля имеют приоритет над этим файлом. Файл — базовый уровень, который нельзя ослаблять без решения ИБ.

## 2. Классификация данных

| Уровень | Название | Что относится | Ответ API | Логи и трассировка | URL / query |
|---|---|---|---|---|---|
| **C0** | Публичные | Справочники, тарифы, названия банков, тексты публичных договоров. | Да | Да | Да |
| **C1** | Внутренние | Технические id (UUID), статусы, коды ошибок, correlation id. | Да | Да | Да (только UUID) |
| **C2** | Конфиденциальные | ПДн, банковская тайна: ФИО, телефон, счета, остатки, суммы, операции, контрагенты. | Только владельцу или роли с доступом; по умолчанию — маскированно | Только маскированно | **Нет** |
| **C3** | Строго конфиденциальные | Секреты аутентификации и подписи: пароли, ПИН, OTP, токены, закрытые ключи, CVV, кодовое слово; документы, удостоверяющие личность; сведения о мерах ПОД/ФТ. | **Никогда** (секреты) / только по особому правилу (документы) | **Никогда** | **Нет** |

Правила, общие для уровней:

| ID | Правило | Тип |
|---|---|---|
| SD-CLS-01 | Уровень объекта = максимальный уровень его полей. Ответ, содержащий хотя бы одно поле C2, обрабатывается как C2. | Практика |
| SD-CLS-02 | Сочетание полей может повышать уровень: телефон + ФИО + сумма → банковская тайна, даже если каждое поле по отдельности замаскировано слабо. | Практика |
| SD-CLS-03 | Агрегированные и обезличенные данные (без возможности установить клиента) могут понижать уровень до C1. | Практика |

## 3. Каталог чувствительных полей

Колонки «Ответ API» и «Логи» указывают правило маскирования из [[#4. Правила маскирования]]. «Полностью» — значение без маскирования.

### 3.1 Персональные данные клиента

| Поле (пример) | Категория | Уровень | Ответ API владельцу | Ответ API о другом лице | Логи |
|---|---|---|---|---|---|
| `lastName`, `firstName`, `middleName` | ПДн | C2 | Полностью | `MASK-NAME-RECIPIENT` | `MASK-NAME-LOG` |
| `birthDate` | ПДн | C2 | Полностью (только в профиле) | Не передавать | `MASK-HIDE` |
| `phone` | ПДн | C2 | `MASK-PHONE` (полностью — только в профиле) | `MASK-PHONE` | `MASK-PHONE` |
| `email` | ПДн | C2 | `MASK-EMAIL` | Не передавать | `MASK-EMAIL` |
| `address` | ПДн | C2 | Полностью (только в профиле) | Не передавать | `MASK-HIDE` |
| `passport` (серия, номер, кем и когда выдан) | ПДн, документ | C3 | `MASK-PASSPORT` | Не передавать | `MASK-HIDE` |
| `snils` | ПДн | C3 | `MASK-SNILS` | Не передавать | `MASK-HIDE` |
| `inn` (физлица) | ПДн | C2 | `MASK-INN` | Не передавать | `MASK-HIDE` |
| `citizenship`, `residency` | ПДн | C2 | Полностью | Не передавать | `MASK-HIDE` |
| `esiaId` / `esiaOid` | ПДн, идентификатор | C2 | Не передавать (служебный) | Не передавать | `MASK-HASH` |
| `deviceId`, `ipAddress`, `geo`, `userAgent` | ПДн (технические) | C2 | Не передавать | Не передавать | `MASK-IP` / `MASK-HASH` |
| Биометрия | Особая категория ПДн | C3 | Не передавать | Не передавать | Никогда |

### 3.2 Банковская тайна и финансовые данные

| Поле | Категория | Уровень | Ответ API владельцу | Ответ API о другом лице | Логи |
|---|---|---|---|---|---|
| `accountNumber` (20 цифр) | Банковская тайна | C2 | `MASK-ACCOUNT`; полностью — только в реквизитах счёта | Не передавать | `MASK-ACCOUNT` |
| `walletNumber` (номер счёта цифрового рубля) | Банковская тайна | C2 | `MASK-WALLET`; полностью — только в реквизитах кошелька | `MASK-WALLET` | `MASK-WALLET` |
| `balance`, `availableBalance` | Банковская тайна | C2 | Полностью | Не передавать | `MASK-HIDE` |
| `amount` операции | Банковская тайна | C2 | Полностью | Получателю — полностью (в его операции) | Полностью — только в защищённом журнале операций; в технических логах `MASK-HIDE` |
| `purpose` (назначение платежа) | Банковская тайна, может содержать ПДн | C2 | Полностью | Получателю — полностью | `MASK-HIDE` |
| Сведения о контрагенте | Банковская тайна, ПДн | C2 | `MASK-NAME-RECIPIENT`, `MASK-PHONE` | — | `MASK-NAME-LOG` |
| История операций | Банковская тайна | C2 | Полностью (своя) | Не передавать | Только id операций |
| `cardNumber` (PAN) | Данные карт (PCI DSS) | C3 | `MASK-PAN` | Не передавать | `MASK-PAN` |
| `cvv` / `cvc` | Данные аутентификации карты | C3 | Никогда | Никогда | Никогда; не хранить |
| `cardExpiry` | Данные карт | C2 | Полностью | Не передавать | `MASK-HIDE` |
| Ограничения и аресты по счёту (`restrictions`) | Банковская тайна | C2 | Тип и сумма — да; основание — общей формулировкой | Не передавать | Только тип |
| Меры ПОД/ФТ, результаты антифрода, скоринг | Служебная тайна | C3 | **Не раскрывать** (общий код отказа) | Не передавать | Только в защищённом журнале ИБ |

### 3.3 Секреты аутентификации и подписи

| Поле | Уровень | Где допустимо | В OAS |
|---|---|---|---|
| `password`, `pin`, `codeWord` | C3 | Только в теле запроса установки или проверки; по TLS. | `writeOnly: true`, `format: password`; никогда в ответах. |
| `otp` / `confirmationCode` | C3 | Только в теле запроса подтверждения. | `writeOnly: true`; `pattern` длины кода. |
| `accessToken`, `refreshToken` | C3 | Только заголовок `Authorization` и ответ сервера авторизации. | Не описывать в схемах бизнес-API. |
| ESIA authorization code / токены ЕСИА | C3 | Только между бэкендом банка и ЕСИА. | Мобильному клиенту не возвращать. |
| Закрытый ключ ЭП | C3 | Только на устройстве клиента или в СКЗИ. | **Отсутствует в API.** |
| Открытый ключ, CSR | C1 | Передаётся на сервер. | `writeOnly` в запросе выпуска. |
| Сертификат ключа проверки ЭП | C1 / C2 | Можно возвращать владельцу. | Отдавать метаданные (серийный номер, срок, статус), не весь сертификат, если он не нужен клиенту. |
| `signature` | C1 | Тело или заголовок запроса. | Не логировать полностью (`MASK-HASH`). |
| `Idempotency-Key`, `X-Request-Id` | C1 | Заголовки ([[oas-conventions#7. Заголовки]]). | Не должны содержать ПДн (только UUID). |

## 4. Правила маскирования

Общие соглашения:
- Символ маскирования — `*`. Длина маски фиксированная или повторяет длину значения — указано в правиле.
- Маскирование выполняется **на сервере**. Клиент не получает немаскированное значение «на всякий случай».
- Маскированное значение передаётся в **отдельном поле** с суффиксом `Masked` (`phoneMasked`), чтобы клиент не мог спутать его с полным значением и случайно отправить обратно.

| Код | Для чего | Алгоритм | Пример: исходное → маска | Тип |
|---|---|---|---|---|
| `MASK-NAME-RECIPIENT` | ФИО другого лица (получателя перевода) | Имя и отчество полностью + первая буква фамилии с точкой. | Иванов Иван Иванович → `Иван Иванович И.` | Практика (как в СБП) |
| `MASK-NAME-LOG` | ФИО в логах | Первая буква каждой части + `*`, длина фиксированная (3). | Иванов Иван Иванович → `И*** И*** И***` | Решение |
| `MASK-PHONE` | Номер телефона | Код страны и последние 4 цифры видны, остальное — `*`. | `+79161234567` → `+7 *** ***-45-67` | Практика |
| `MASK-EMAIL` | Электронная почта | Первый символ локальной части + `***` + `@` + домен полностью. | `ivan.petrov@mail.ru` → `i***@mail.ru` | Практика |
| `MASK-ACCOUNT` | Номер банковского счёта | Последние 4 цифры. | `40817810099910004312` → `**** 4312` | Практика |
| `MASK-ACCOUNT-EXT` | Номер счёта в выписке для сверки | Первые 5 (балансовый счёт 2-го порядка) + последние 4. | `40817810099910004312` → `40817 *** 4312` | Решение |
| `MASK-WALLET` | Номер счёта цифрового рубля | Последние 4 символа. | → `**** 7788` | Решение (формат номера — проверить) |
| `MASK-PAN` | Номер карты | Первые 6 и последние 4 цифры (по PCI DSS). | `2202201234567890` → `220220******7890` | Норма (PCI DSS) |
| `MASK-PASSPORT` | Паспорт РФ | Серия скрыта, номер — последние 3 цифры. | `45 12 345678` → `** ** ***678` | Решение |
| `MASK-SNILS` | СНИЛС | Видны только последние 2 цифры (контрольное число). | `112-233-445 95` → `***-***-*** 95` | Решение |
| `MASK-INN` | ИНН физлица | Последние 4 цифры. | `771234567890` → `********7890` | Решение |
| `MASK-IP` | IP-адрес в логах | IPv4 — обнулить последний октет; IPv6 — оставить /48. | `192.168.10.25` → `192.168.10.0` | Практика |
| `MASK-HASH` | Идентификаторы для корреляции в логах | Ключевой хеш (HMAC) со служебным ключом; без соли хеш от телефона легко перебирается. | `+79161234567` → `h:3f9a…c21` | Практика |
| `MASK-HIDE` | Полное скрытие | Поле не выводится или выводится `[REDACTED]`. | → `[REDACTED]` | Практика |
| `MASK-NONE` | Без маскирования | Значение полностью. | — | — |

> [!warning] Маскирование — не защита от перебора
> По маскированному телефону и имени `Иван Иванович И.` злоумышленник может проверить, есть ли у человека кошелёк. Поэтому поиск получателя дополнительно защищается лимитами частоты (SD-API-08).

## 5. Правила проектирования API

| ID | Правило | Тип | В OAS |
|---|---|---|---|
| SD-API-01 | **Минимизация**: в ответ включаются только поля, нужные экрану или процессу. Данных «на будущее» нет. | Норма (152-ФЗ) | Отдельные схемы для списка (`WalletSummary`) и детали (`WalletDetails`). |
| SD-API-02 | **Нет C2/C3 в URL и query**: пути и query-параметры попадают в логи прокси, шлюзов и браузеров. | Практика | Идентификаторы в путях — только UUID; поиск по телефону — `POST /recipients/search` с телефоном в теле. |
| SD-API-03 | **Непрозрачные идентификаторы**: вместо номера счёта или кошелька в путях — внутренний UUID. | Практика | `accountId: format uuid`; номер — отдельным полем ответа. |
| SD-API-04 | **Маскированные значения по умолчанию**: ответы содержат `*Masked`-поля; полные значения — только в операциях, которые явно для этого предназначены. | Решение | `phoneMasked`, `accountNumberMasked`. |
| SD-API-05 | **Раскрытие полного значения** (реквизиты счёта, номер кошелька целиком) — отдельная операция, с повышенной аутентификацией при необходимости и записью в аудит. | Практика | `GET /accounts/{id}/requisites`; описать в `description` требование step-up. |
| SD-API-06 | **Секреты только на вход**: пароли, OTP, ПИН — `writeOnly`, никогда не возвращаются и не попадают в `example` реальными значениями. | Практика | `writeOnly: true`, `format: password`. |
| SD-API-07 | **Ошибки без ПДн**: `detail` в Problem Details не содержит значения полей запроса, ПДн и сведений о мерах ПОД/ФТ. | Практика | Описание поля `detail` в схеме `Problem`. |
| SD-API-08 | **Защита от перебора**: операции поиска по телефону, номеру кошелька и проверки кодов ограничены по частоте на клиента и устройство. | Практика | 429 + `Retry-After`; описать лимит в `description`. |
| SD-API-09 | **Единый ответ «не найдено»**: поиск получателя не различает «номера нет» и «номер есть, но кошелька нет», если это раскрывает лишнее. | Проверить (зависит от UX) | Один код `RECIPIENT_WALLET_NOT_FOUND`. |
| SD-API-10 | **Запрет кэширования**: ответы с C2/C3 не кэшируются клиентами и прокси. | Практика | Заголовок ответа `Cache-Control: no-store`. |
| SD-API-11 | **Без ПДн в заголовках** (кроме `Authorization`). | Практика | — |
| SD-API-12 | **Тонкие события**: callbacks и webhooks несут только id и статус; детали получатель забирает отдельным аутентифицированным запросом. | Практика | Схемы событий без ПДн. |
| SD-API-13 | **Примеры в OAS — только синтетические данные**: телефоны `+7900000xxxx`, вымышленные ФИО, тестовые номера счетов. | Практика | `example` / `examples`. |
| SD-API-14 | **Шифрование канала**: TLS 1.2+; для интеграции с платформой ЦР и государственными системами — криптография по ГОСТ (СКЗИ) в соответствии с требованиями ИБ. | Норма / Проверить детали | `servers` только `https`; описание в `info.description`. |
| SD-API-15 | **Запрет tipping-off**: клиенту не сообщается, что операция или кошелёк ограничены в рамках ПОД/ФТ или антифрода, и по какому правилу. | Норма (115-ФЗ) | Общие коды `OPERATION_DECLINED_BY_SECURITY`, `WALLET_OPENING_REFUSED`. |
| SD-API-16 | **Данные ЕСИА** используются только для цели, на которую дано согласие (открытие кошелька), и не возвращаются клиенту целиком. | Норма (152-ФЗ) | Ответ — статус шага, а не профиль из Госуслуг. |
| SD-API-17 | **Согласие до передачи**: ПДн передаются третьему лицу (платформа, ЕСИА) только при наличии основания (договор, закон, согласие). | Норма (152-ФЗ) | Проверка `Consent.GRANTED` перед шагом; 422 при отсутствии. |

## 6. Логи, трассировка, мониторинг

| ID | Правило | Тип |
|---|---|---|
| SD-LOG-01 | Тела запросов и ответов с C2/C3 не пишутся в технические логи целиком; применяется маскирование по каталогу. | Практика |
| SD-LOG-02 | C3-секреты (пароли, OTP, токены, ключи, CVV) не попадают в логи ни в каком виде, даже маскированно. | Практика / Норма для CVV |
| SD-LOG-03 | Для корреляции событий одного клиента используется `MASK-HASH` или внутренний id, а не телефон. | Практика |
| SD-LOG-04 | Журнал аудита (кто открыл, изменил, раскрыл данные клиента) ведётся отдельно от технических логов, защищён от изменения, с ограниченным доступом. | Норма (ГОСТ Р 57580.1) |
| SD-LOG-05 | Метки метрик и трейсов (labels, span attributes) не содержат ПДн. | Практика |
| SD-LOG-06 | Срок хранения логов и журналов задаётся политикой банка; по его истечении данные удаляются. | Практика / Проверить срок |

## 9. Нотация в OAS

Каждое чувствительное поле получает расширение `x-sensitivity`:

```yaml
x-sensitivity:
  level: C2            # C0 | C1 | C2 | C3
  category: PII        # PII | BANK_SECRECY | AUTH_SECRET | ID_DOCUMENT | AML | CARD_DATA
  masking: MASK-PHONE  # код из раздела 4
  log: MASK-PHONE      # правило для логов, если отличается
```

Пример фрагмента схемы:

```yaml
components:
  schemas:
    RecipientPreview:
      type: object
      description: Данные получателя для сверки перед переводом. Полные ПДн не передаются (SD-API-01, BR-DR-TRF-03).
      required: [recipientId, displayName, phoneMasked]
      properties:
        recipientId:
          type: string
          format: uuid
          description: Непрозрачный идентификатор получателя для последующего перевода.
          x-sensitivity: { level: C1 }
        displayName:
          type: string
          example: Иван Иванович И.
          x-sensitivity: { level: C2, category: PII, masking: MASK-NAME-RECIPIENT, log: MASK-NAME-LOG }
        phoneMasked:
          type: string
          pattern: '^\+7 \*{3} \*{3}-\d{2}-\d{2}$'
          example: '+7 *** ***-45-67'
          x-sensitivity: { level: C2, category: PII, masking: MASK-PHONE }

    WalletPasswordSetup:
      type: object
      required: [password]
      properties:
        password:
          type: string
          format: password
          writeOnly: true
          x-sensitivity: { level: C3, category: AUTH_SECRET, masking: MASK-HIDE, log: NEVER }

```

Заголовок `Cache-Control: no-store` подключается общим компонентом `components.headers.CacheControlNoStore` ([[oas-conventions#7. Заголовки]]).

Чек-лист для каждой операции:
1. Есть ли в пути или query C2/C3? → перенести в тело или заменить UUID.
2. У всех полей C2/C3 задан `x-sensitivity`?
3. Секреты — `writeOnly`, без реальных `example`?
4. Ответы с C2/C3 содержат заголовок `Cache-Control: no-store`?
5. Ошибки не раскрывают ПДн и меры ПОД/ФТ?
6. Поиск и проверки кодов защищены лимитом (429)?
7. Примеры синтетические?

## 11. Открытые вопросы

1. Формат номера счёта цифрового рубля и правило его маскирования (`MASK-WALLET`).
